## 引言

裸机开发意味着不依赖操作系统，直接在硬件上写代码。对 STM32 初学者来说，理解「寄存器 → 库函数 → BSP 分层」这条路线，是打好嵌入式基础的关键。

## 寄存器 vs 库函数 vs BSP

- **寄存器**：直接读写内存地址，最底层、最透明，但可读性差、易出错。
- **库函数（HAL）**：STM32 官方封装，易上手、可移植，但抽象层带来一定开销。
- **BSP（板级支持包）**：在 HAL 之上再封装一层，把「点灯」「读传感器」变成语义清晰的接口，便于在多个项目间复用。

三者不是替代关系，而是逐层向上抽象。

## 常用外设入门

- **GPIO**：一切控制的起点，先点亮一颗 LED。
- **定时器**：产生 PWM 输出，是电机调速与舵机控制的基础。
- **CAN**：差分总线，抗干扰强，适合机器人多节点通信，需注意波特率与报文 ID 仲裁。
- **I2C**：两线总线，适合连接传感器，注意上拉电阻与地址冲突。

## 一个寄存器配置示例

以直接配置 GPIO 为例，体会寄存器编程的「原始感」：

```c
// 使能 GPIOA 时钟（RCC AHB1 使能寄存器）
RCC->AHB1ENR |= (1U << 0);

// 将 PA5 配置为输出模式
GPIOA->MODER &= ~(3U << 10);
GPIOA->MODER |=  (1U << 10);

// 点亮 PA5 上的 LED
GPIOA->ODR |= (1U << 5);
```

## 何时引入 FreeRTOS

当程序出现多个「看似同时」的任务——例如一边采样传感器、一边跑 PID、一边响应串口——裸机的「大循环 + 中断」开始难以维护时，就可以引入 FreeRTOS。它把任务抽象成独立的执行单元，通过调度器切换，但也会带来栈空间、优先级反转等新问题。我的建议是：先把裸机玩熟，再上 RTOS，才能真正理解它解决了什么。

## 小结

- 从寄存器理解硬件，再用 HAL 和 BSP 提高效率。
- GPIO、定时器是入门必练，CAN、I2C 是机器人通信的基础。
- FreeRTOS 在任务复杂到难以用「中断 + 大循环」管理时引入，而不是一开始就上。
